# App Logs

App Logs records meaningful application and workspace events for operational review. It tells who triggered each event (**Triggered by**: the person, or `system`, shown in red as **System** tagged *application*, for every event of the application itself, which no signed-in user performed) from where it ran (**Executed by**, never empty): the module whose page a signed-in person used (its title in Interface Settings, tagged *module*); the **Server** on its own, tagged *Scheduler* (scheduled backups and Reporting Jobs), *Background job* (processing and mapping CDRs, combined tables, Scoring calculations, PPT and chart jobs, package and transfer jobs), *Idle task* (PPT warm-up, NQ indexing, Map Areas fill) or *Startup* (each start of the application, upgrades and the recovery of interrupted work); a **Remote server**, tagged with its name, for the transfers it sends; or **Public**, tagged *Sign-in*, *Access request* or *Bug report*, for the pages used without signing in. Events of earlier versions, which did not record where they ran, take it from their action, or show **Application** tagged *not recorded*.

> [!NOTE]
> **Two different scopes.** App Events belongs to the active workspace. Execution Log shows output from the running server process.

> [!IMPORTANT]
> **Server restarts.** Execution Log capture resets when the server restarts; it is not a replacement for persisted workspace events.

## Access and workspace scope

App Logs is available to authenticated users with the existing application roles. App Events show the active workspace's audit entries. Open a workspace in Workspace Management to review its events. When no workspace is active, the App Events table is unavailable; the live Execution Log still shows output from the running server process.

## App Events

Use the filters to narrow entries by **Date**, **Triggered by**, **Executed by**, **Type** and **Action**. Each filter is a list where you tick one or several values (search the list, **Include** / **Exclude** or **Select All / None**, which stay at its top while its values scroll); the list is as tall as most of the window and as wide as its values need, opening above its button when there is more room there; an event is shown when it matches one of the values ticked in every filter, and a filter with no value ticked shows every event (*All users*, *All dates*…). A filter set to **Exclude** works the other way round: it shows every event except those of the values ticked, which are crossed out in red, so the events of values that appear later are shown too, and its button reads in red, for example *All except login* or *2/9 excluded*. Each filter has its own mode, and switching it keeps the values ticked. The values a filter leaves out stay in its list while the other filters change, as long as an event has them. Each filter offers the values of the events that the other filters leave, except **Date**, which always lists every date of the events whatever the other filters. **Date** offers **Last Day** first, above a line: the newest date of the events, whatever day it is, to include or to exclude like any value; while it is ticked the button reads *Last Day* and the days are unticked and disabled, and unticking it enables them again. The **Triggered by** filter lists `system` first, in red as **System** tagged *application*, with a line of its own, then the default users (super, admin and demo) tagged *default user*, and after another line the other users by their first and last name (their username when they have none); other names of no account show as they are. User matching is case-insensitive. The **Executed by** filter lists the **Server** places first, then remote servers, public pages and the modules in their order, with a line between the groups. The **Date** column shows each event's date with its time as a green badge below. The **Triggered by** column shows each person by first and last name with the username as a badge below (the username alone when the account has no name or no longer exists), and `system` in red as **System** tagged *application*; the **Executed by** column shows the place with its tag below. App Events shows the newest 10,000 events of the workspace, 100 a page with a pager below the table; every event is kept, and exports and backups include them all. The server filters the events, and the count beside **Refresh** shows how many there are, or how many match the filters out of them. The browser remembers the values ticked, and whether each filter includes or excludes them, for the next visit, and a list stays open as it is while the table refreshes: values of new events join it when it closes. Select **Clear Filters** to restore the full list (every filter back to **Include**), or **Refresh** to request the latest entries. The table refreshes automatically every five seconds, and only fetches the events again when one was added, imported or deleted.

**Details** describes each event in one sentence. Each save of a user account lists only the fields it changed, from the previous value to the new one (names, role, active, Modules Profile, Workspace Groups and workspaces, and whether the password changed, never its value), for example `User EUSER01: role user-viewer → user-editor; activated; Workspace Groups +UK.`, or says that it was saved with no changes; creating or deleting a user records the account as it was. The changes of several users at once, Modules Profiles, Workspace Groups, Interface Settings, the application configuration, email delivery, scheduled backups and the backup selection, and Operator and Vendor Maps also say what changed; other events name the action and the values recorded. Scoring calculations and exports name their Saved Filter as `saved filter ID 57 (favourite)` when it is one of the Favourites Filters (marked with the star), and as `unsaved filter ID 57` otherwise, since only the Favourites Filters are kept. Events of earlier versions, which kept only what was saved, show those values and say that they did not record which fields changed. **Raw details**, folded by default, unfolds the data recorded with the event, for troubleshooting.

Events record every start of the application (`application_started`, written by `system` in every workspace: first in the active workspace it opens and, once the application is ready, in the others, except one being duplicated or never opened yet; with the version, the active workspace, how long it took to be ready, the address it listens on, the Python version, the platform and the process ID, and, as an Error, why the active workspace could not be opened), every action of the users and the work that runs for them: signing in and out (a failed sign-in is recorded with the `system` user and the login typed in its details); opening, closing, creating, renaming, duplicating and deleting workspaces (a deleted workspace is recorded in the workspace open at that moment), clearing their cache and changing their access; uploading (or cancelling an upload), processing, mapping and deleting datasets and downloading their CSV previews; Datasets Analysis and Network Insights analyses, Query Builder runs and their cancellation, and Scoring & GAP Analysis calculations (`scoring_calculation_requested`); the follow-up of the NQ Analysis Center (changes to one call or to several, comments and their edits and deletions, imports and exports); generating, downloading, stopping and deleting reports, Reporting Job runs and PPTs; configuration changes; exports of data, chart data, PPT Templates, Designs, Scoring results and reports (also the charts and tables of Scoring & GAP Analysis, Network Insights, Non-Qualified Calls, Chart Builder and PPT Designer downloaded as images or copied as screenshots), methodologies and report configurations; Ticket Center tickets (opening, editing, comments, screenshots and files added and deleted, attention, type changes and deletion); imports (each uploaded package with its file and kind, and each refused file with the reason), backups, export packages and transfers to and from other servers with their outcome; and requests to stop background tasks. Opening pages, previews, filter selections and status refreshes are not recorded. A Scoring & GAP Analysis calculation that fails writes a `scoring_calculation_failed` event with its error and where it happened. Background events keep their requester in **Triggered by** and show the **Server** in **Executed by**. Events that earlier versions recorded under the name of a process instead of `system` (`import`, for the table columns taken from an imported Non-Qualified Calls configuration) belong to `system` when the workspace opens, with that process in their details, and a `migrate_app_event_users` event records how many changed; App Events imported or restored from older packages come in the same way.

**App Events** also travel on their own, as App Events in [Import / Export / Transfer](administrator-config.md#export-targets) and in the Workspace Content of [Backup Protection](super-admin.md#backup-protection): importing or restoring them adds to a workspace the events it does not have, and App Events lists every event by its date and time, so imported events take their place among the others.

## Execution Log

The Execution Log displays live output captured from the current server process and uses the configured application timezone. It can help diagnose runtime and background-task failures. It contains only output captured since the process began; restarting starts a new capture. It opens on its latest lines and follows the new ones as they arrive; scrolling up stops it so you can read, and **Go to the end**, in its bottom corner while you are away from the end, or scrolling back down to the end, follows the latest lines again.

For workspace settings, see [Workspace Config](workspace-config.md). For runtime settings, see [Application Config](app-config.md).
